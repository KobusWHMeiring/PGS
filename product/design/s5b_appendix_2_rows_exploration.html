Part 2 The shape of the problem

Two facts pull in opposite directions, and the tension is the whole decision.

What the repository already has

A reviewed 30-row pairing, signed by the owner on 2026-10-21, with two tests proving the pairing against the paper — and a measured column boundary per page in TABLE_BANDS. 39 of 41 cells are already locators the page prints.

What the repository may not do

Run an extractor. The PRD is explicit: “Do not re-open the Document AI key and do not re-run the arm evaluation.” And the one thing S5 exists to stop is a person typing a table into the corpus.

So the question is not “how do we read the remaining 19 rows?”. It is: is promoting an existing reviewed pairing into a verified structure the same act as authoring a table?

The distinction that decides it. A cell is characters someone wrote into the corpus. A locator is words used only to find where the page already holds it — the emitter refuses anything it cannot find and splices out the page's own characters. The reviewed rows can be promoted only if they enter as locators, every one of which the emitter re-verifies. That is testable, and the test is cheap.

The asymmetry that makes this urgent rather than interesting: Appendix 7 needs the same capability. Its cells also wrap inside a column (Aeration or oxygenation / using gaseous oxygen, with Air, beside it on the same printed line). A column-boundary declaration built once serves both tables.

Part 3 The options

Three real options, plus one that is not available and should be named so nobody proposes it again.

A

Declare the column band and the two continuations; emit all 30 rows

Promote the reviewed rows to locators. Add a reviewed band: declaration (the measured column start, per page) so the emitter cuts a cell at the neighbouring column, extend the continuation branch to honour it, teach the emitter the hyphen rule the harness already has, and declare the seaweed row's cross-page tail. Thirty rows, seven dividers, one block. APPENDIX_2_ROWS, TABLE_ROWS, rows_for and the chunks_for_rows path all go.

column 0 60 page 76 Farmyard manure, slurry and urine | Shall not constitute the main | source of nitrogen in the | absence of complimentary and band cut ^ (TABLE_BANDS[76] = 60)

The cut is the declaration. Left of it is the substance cell, right of it the condition cell; the emitter still slices the page's own characters, so a cell it cannot find is still a refusal by name.

For

  • 39 of 41 cells are already runs of the band-sliced page — this is verification, not authoring (Part 1, measurement 2).
  • Deletes the bespoke handling, which is the PRD's §6 criterion — the only option that does.
  • The band declaration is shared with Appendix 7 (S5-c), so one capability closes two slices.
  • The two exceptions are requirement 4's own case and the harness's existing hyphen rule — neither is new semantics.

Against

  • Three code changes to the emitter at once (band, hyphen, continuation) — each must be refused-then-declared, so it is the most expensive option by hours.
  • It makes reviewed data a locator source, which is a precedent. If that precedent is wrong, it is wrong in a way that outlives the slice.
  • TABLE_BANDS is currently only used to verify; using it to slice changes what the number means, and the docstring must say so.
B

Emit the 11 rows the arm actually read

Take the qualifier page as a block — the reviewed columns field handles its merged header — and leave rows 12–30 as they are.

For

  • Every character is the arm's own read — nothing is promoted.
  • Proves the band is not needed, if that turns out to be true.

Against

  • Deletes nothing. APPENDIX_2_ROWS must stay for the 19, so TABLE_ROWS/rows_for/chunks_for_rows all stay.
  • Two storages for one table — the artefact block for page 76 and Python for the rest. That is worse than either end state, and it is new.
  • The ingest would have to choose per page, which is a second rule nobody asked for.
  • PRD §6's “the bespoke handling is deleted” stays unmet, so the PRD stays open.
C

Stop at Appendix 6a and close S5 as “partly landed”

Ship what session 1q already has (6a is a block, 20 chunks carry column meaning, the Python is deleted for 6a), record Appendix 2 and 7 as named debt, and move on to other work.

For

  • Honest, already true, and zero risk — it is the current state.
  • The PRD's own §7 risk table says a hand-review “fix” for 6a/7 is the thing to avoid; stopping avoids it.
  • Frees the next session for a differently-shaped slice.

Against

  • Appendix 2's 30 rows keep no column meaning in the artefact, and its quote-pairing risk (the straw/wood defect this PRD opens with) stays live for 19 rows.
  • S5 is the last slice. Leaving it open leaves the PRD open indefinitely, and the next session re-derives Part 1 to decide again.
D

Run the Layout Parser once on printed 77–78 not available

The clean answer on paper: one arm call, three pages, complete structure. It is excluded by the PRD's own constraint (“do not re-open the Document AI key, do not re-run the arm evaluation”) and by requirement 10's spirit — the gate must not need an extractor. Recorded so that nobody re-proposes it as a fresh idea.

Part 6 Recommendation

A — declare the band and the two continuations, and emit all 30 rows. In this order, each step refused-then-declared:

  1. The band. A red test that the emitter refuses a cell whose words cross the declared column boundary; then band: in saoso.reviewed.json per page, cut with the already-measured TABLE_BANDS number. TABLE_BANDS' docstring changes from “used to verify” to “used to slice, and verified by test_tables.py”.
  2. The hyphen. A red test for cobalt- / sulphate; then the emitter adopts the rule the harness already has, word-boundary checked.
  3. The cross-page tail. A red test for the seaweed row; then an explicit tail: declaration naming iii) fermentation. and the page it prints on — requirement 4's own case, declared rather than inferred.
  4. The block. Emit, diff, `check_tables --doc saoso --rows 30,20`, delete APPENDIX_2_ROWS/TABLE_ROWS/rows_for/chunks_for_rows.

What it changes: Appendix 2's 30 chunks carry their column meaning; the artefact holds the pairing; the ingest has one path; the PRD's §6 loses two of its five open criteria. What it does not change: the reviewed pairing — that was signed in 2026-10-21 and no locator can alter it.

What would change my mind

  • If more than a handful of band-sliced cells fail. Today it is 2 of 41. If step 1's test shows the band does not fit the page — say more than five cells crossing it — then the review is not a locator set and A becomes authoring in disguise. Take B and record why.
  • If the cross-page tail turns out to be common. One declared tail is a declaration; five is a pattern, and a pattern wants the arm's page range, not a per-cell exception.
  • If Appendix 7's band needs a different shape (a leading gutter plus four columns). Then the band is Appendix 2's alone and A's cross-slice benefit disappears — but A is still the only option that deletes the bespoke handling.
