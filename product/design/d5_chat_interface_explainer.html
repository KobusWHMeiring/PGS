How the grounded chat works

How /ask/ turns a typed question into a cited answer, what happens when it cannot, and how the conversation, the history and the cost are kept under control.

This is an explainer, not a proposal. Every claim below points at a file, a test or a command you can run. The page is self-contained: no CDN, no external font, no network. It opens from the filesystem.

Part 1 · What is actually true

The pieces, and the shape they make

The chat is a thin view over one service, backed by a small history model and the existing corpus library. Nothing in the chat knows how the standard was parsed; nothing in knowledge/ knows a user exists.

The one-line contract

In:  session_uuid, question (<= 500 chars)
Out: GroundedAnswer(text, citations,
                    insufficient_context,
                    escalated_query_id)
Side effects: 2 ChatMessage rows;
             1 EscalatedQuery when refused
Fails: RateLimitedError, UpstreamModelError
       -- never a fabricated fallback

The public identifier is a UUID, never the integer primary key. A session is pinned to a StandardSet, so the corpus boundary is a property of the conversation rather than a rule the model has to remember.

Part 2 · The shape of the problem

Why this is not a text box over an API

Four asymmetries drive every design choice below. They are not preferences; each one has a failure mode that looks fine in a browser.

Asymmetry 1

A confident wrong answer is worse than a refusal

The group's credibility is that every sentence can be traced to SAOSO, the OPP, the Basic Production Principles or the certification landscape. A model answering from memory can sound exactly right and be wrong. So the refusal is the product, not an error state.

Asymmetry 2

A natural question is not a search phrase

Postgres's websearch_to_tsquery joins words with AND. Measured on the shipped corpus: "What does the standard require for traceability?" returned zero chunks, while "traceability OR standard" returned chunks.

Asymmetry 3

Common words outrank the word that carries the question

A plain OR let a landscape paragraph containing “standard” outrank the SAOSO clause containing “traceability”. The rare word is the signal; the common word is the noise. Retrieval searches the rarest term first, then the OR fallback.

Asymmetry 4

A cached answer can outlive its contract

The cache stores the model reply, not the rendered answer. Citations are re-audited on every hit, and PROMPT_VERSION is part of the key. Change the prompt or retrieval without bumping it, and Redis serves an answer produced under the old rules.

The rule that follows. A result is grounded only when all of these hold: retrieval returned at least one chunk from the session's set; the model did not set insufficient_context; it returned at least one citation; every reference is in the retrieved set; every sub-reference is in that chunk's stored offset map; every quote is a whitespace-normalised substring of the cited chunk. Anything else produces exactly one refusal.

Part 3 · Path of a question

What happens after the visitor presses Ask

The order is a correctness property, not an implementation detail: the rate limit runs before any row is written, retrieval runs before the model, and the citation audit runs before the answer is stored.

  1. The browser posts the form. With JavaScript, HTMX sends the same POST and asks for a fragment; without it, the browser posts normally and receives the whole page. The server renders one thread template either way.
  2. The form validates. A blank or over-500-character question never reaches the service. stop
  3. The service validates again and checks the rate limit. The service is reachable without the form, so the cap lives in both places. A spent per-IP budget raises RateLimitedError before a message is written. stop
  4. The session is resolved or created. A GET does not create a conversation. The first question creates a ChatSession, pins it to the default StandardSet, and stores its UUID in the Django session cookie.
  5. The user message is written, then retrieval runs. The query is stripped of function words and searched rarest-term-first, always filtered to the session's corpus before ranking.
  6. No chunks means no model call. The assistant refuses and records an EscalatedQuery immediately. Calling the model with an empty context is exactly how a bot starts guessing. stop
  7. The cache is consulted. The key is PROMPT_VERSION + StandardSet + corpus fingerprint + normalised question hash. A hit skips Gemini; citations are still re-audited against fresh chunks.
  8. Gemini is called once, with JSON output. The prompt contains the numbered passages and the bounded conversation window. The schema is {answer, citations[{section_ref, sub_ref, quote}], insufficient_context}.
  9. The audit decides. The model's flag is not trusted on its own. Empty citations, an un-retrieved reference, an absent sub-ref or a quote that is not in the chunk all refuse the whole answer. stop
  10. The exchange is recorded. The assistant row stores the answer, latency, model, token counts and every retrieved chunk. A refusal also writes one EscalatedQuery for the administrator.
  11. The view renders. A plain POST returns the full page with the answer and citations. An HTMX POST returns only the thread fragment. A 429 or 503 returns the fragment with a warm notice, never a guess.

The shape of the refusal. I cannot find a definitive answer in the SAOSO standard or the Outeniqua PGS documents. The exact string is D17's, and the test is test_the_refusal_is_the_d17_wording. It names four documents, not only SAOSO, because the OPP answers questions the standard does not: fees, joining, committee procedure.

Part 4 · The stops

Every gate, what triggers it, and what the visitor sees

A “stop” is a point where the system declines to continue. Some are limits, some are grounding failures, and one is a transport failure. None of them produces a fabricated answer.

Question cap blank, or more than 500 characters Form message; no session, no row, no model call. test_the_question_cap_is_read_at_call_time; test_an_over_long_question_is_rejected_without_calling_the_service
Per-IP rate limit more than CHAT_RATE_LIMIT questions in the fixed window HTTP 429 with Retry-After; the question is not written and the model is not called. test_the_rate_limit_allows_the_budget_then_refuses; test_answer_question_refuses_before_writing_when_rate_limited
Nothing retrieved FTS returns no chunk in the session's set Exact refusal + EscalatedQuery(INSUFFICIENT_CONTEXT); the model is never called. test_no_retrieved_chunks_means_the_model_is_never_called

No citations the flag is false but citations is empty Exact refusal + EscalatedQuery(NO_CITATIONS). The boolean is not trusted alone. test_refusal_fires_on_empty_citations_even_if_the_flag_is_false
Unknown reference a section_ref or anchor not in the retrieved set The whole answer is refused; the citation is not trimmed and kept. test_a_citation_naming_an_unretrieved_ref_is_dropped_and_forces_refusal
Wrong corpus a chunk whose standard_set_id differs from the session's Refused. The scope is checked in retrieval and again in the audit. test_no_answer_can_cite_a_chunk_outside_the_session_standard_set

Paraphrased quote the quote is not a whitespace-normalised substring of the cited chunk Refused. A citation that cannot be checked is not a citation. test_a_quote_that_is_not_in_the_cited_chunk_is_rejected
Runaway answer more than 6,000 characters Refused rather than truncated: truncation silently changes what the model said. covered by the refusal path in answer_question

Conversation window more than CHAT_HISTORY_MESSAGES prior turns The model receives only the last N messages; the database keeps all of them. test_the_history_sent_to_the_model_is_capped

Why the audit is all-or-nothing

One invented reference beside two good ones is still an answer that contains an invented reference. Trimming the bad one would leave a confident answer with no visible trace of the hallucination. The test test_the_audit_is_all_or_nothing pins that decision.

Why the refusal is warm, not red

DESIGN §7.9: a boundary drawn confidently is not a malfunction. The refusal bubble uses the warm dark ground and offers the administrator as the next step. The same styling is used for 429 and 503 notices.

Part 5 · History and sessions

What is kept, where, and for how long it is sent

Chat lives in core, not knowledge, because it is user-owned. The corpus library stays a library: no users, no sessions, no views. Three models carry the conversation.

ChatSession public_uuid · user? · standard_set · ip_hash · user_agent · created_at
1 → many
ChatMessage role · content · latency_ms · model · prompt_tokens · completion_tokens · retrieved_chunks M2M
1 → 0..n
EscalatedQuery question · reason · status · answered_by · answer · answered_at
StandardSet the corpus boundary; a session is pinned to one
1 → many
DocumentChunk section_ref / anchor · sub_refs · text · page
cited + retrieved
Redis cache model reply keyed by prompt version, set, corpus fingerprint, normalised question

Session lifecycle

  • GET /ask/ creates nothing. A reader who leaves leaves no row and spends no budget.
  • The first question creates the session, pins it to the single default StandardSet, hashes the client IP, and stores the UUID in the Django session cookie.
  • Anonymous first, member later. ChatSession.user is nullable. When the same visitor signs in, attach_user() sets the user on the existing row; the history is not copied or restarted.
  • Pinned corpus. The set is a foreign key with PROTECT. A conversation that started against v2.1 keeps answering from v2.1 even after the deployment ingests v2.2.

What a message records

  • Both sides of every exchange: the question as typed and the answer or refusal.
  • Cost: latency_ms, model, prompt_tokens, completion_tokens. A cache hit stores zero tokens rather than double-counting.
  • Evidence: the M2M to every retrieved chunk, not only the cited ones. When a refusal is reviewed, the useful question is “what did the retriever give the model?”
  • Ordering: created_at, id, because two rows written in the same millisecond would otherwise render arbitrarily.

The window sent to Gemini

CHAT_HISTORY_MESSAGES (default 8) prior messages, oldest first. The current question is passed separately, so the model sees a bounded transcript plus the numbered passages. The full history stays in Postgres and is rendered on a later GET.

The window is a cost and prompt-injection control as much as a relevance one: an unbounded transcript grows the prompt on every turn and gives an attacker more surface.

Escalation, not a dead end

Every refusal writes one EscalatedQuery with the question, the reason and OPEN status. The admin is editable: answering stamps answered_at, answered_by and ANSWERED. A gap in the corpus becomes a question a person can answer.

The message FK is SET_NULL: deleting a conversation must not erase the evidence that the gap exists. The question stands on its own.

Cache key, exactly. chat:answer:<PROMPT_VERSION>:<standard_set_id>:<corpus_fingerprint>:<sha256(normalised question)>. The corpus fingerprint is chunk count + max id + the documents' sha256 list. Changing the prompt or retrieval without bumping PROMPT_VERSION means an old answer outlives the contract it was produced under.

What was run, and what the tests cannot see

Commands that were run

  pytest               -> 465 passed

The real answer was checked in a browser with JavaScript on, with JavaScript off, and at 390 px. The citation disclosure, the 429/503 notices and the refusal link were opened, not just asserted.

The hazard this session found

search('What does the standard require for traceability?')
  -> []                      # websearch_to_tsquery ANDs

search('traceability OR standard')
  -> chunks                  # but common words win

search_terms(['standard', 'traceability'])
  -> rarest first, then OR   # the fix

Recorded with evidence in product/docs/context/testing_hazards.md §2.4. Without it, a phrase-shaped test suite stayed green while every real question refused.

What no test here can see. Whether a citation that resolves is topically the right passage. The first live answer on 2026-10-19 cited a landscape paragraph for a question about the standard's traceability requirement. The prompt now prefers governing documents, and the retrieval now puts the SAOSO clause first, but only UAT Scenario 2 can judge whether the result reads as an answer or as a near-miss.

Still open

  • D's UAT Scenarios 1, 2 and 6 are unsigned.
  • The corpus has no embeddings; retrieval is lexical only.
  • Topical relevance is a human judgement.

Deliberate choices

  • Refusal is D17's wide-corpus wording, not the old SAOSO-only string.
  • The audit refuses all, not the worst citation.
  • No API key means 503, never a canned answer.

If you change it

  • Bump PROMPT_VERSION when the prompt or retrieval changes.
  • Run a real question, not only a phrase from the standard.
  • Do not add a sixth nav link; link from the showcase and footer.
