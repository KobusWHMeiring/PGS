Where the corpus work stands — and what P4 actually is

The drift slice landed today: a deployment can now tell whether its corpus matches the review that produced it, and the ingest refuses to fall back to the PDF. The plan's next task is P4, the OPP artefact. I ran its first step before recommending it, and the first step does not work. This page is what I found, the four ways forward, and one recommendation.

The question

P4 is written as “generate the OPP draft, review it, declare the edits”. The generator produces an empty draft for every document except SAOSO. So: what is the next slice — repair and review, review anyway, deploy the box, or settle the table-of-contents dependency first?

2The shape of the problem

Not "the OPP needs reviewing". Something more specific: the generator works for exactly one document, and that document is the reason nobody noticed.

2.1 The asymmetry that hid it

read scripts/build_corpus.py:280–290. The generator slices an artefact from a line stream. A parser may declare body_lines() — knowing which pages are the body and which lines are furniture. Only SaosoParser does. Everything else takes the generic branch:

    body_lines = getattr(parser, "body_lines", None)
    if body_lines is not None:
        stream = body_lines(joined)
        ...
        keep = lambda line: not is_furniture(line)   # negated: keep the text
    else:
        lines, _starts, _norm = flatten(pages)
        keep = is_page_furniture                     # NOT negated: keep the page numbers

Two lines below, the writer keeps a line only when keep(line) is true. So for every document without body_lines — the OPP, the landscape, the BPP — the draft keeps the printed page numbers and blank lines and throws the document away.

SAOSO's path (has body_lines)

  1. parse the de-columned, reflowed pages
  2. body_lines() names the body pages
  3. keep = not is_furniture — keeps the text
  4. draft ≈ the document; reviewed into saoso.md
works — and it is the only path ever exercised

Every other document (generic branch)

  1. parse the de-columned, reflowed pages
  2. flatten() gives every line
  3. keep = is_page_furniture — keeps the furniture
  4. draft = page numbers; CORPUS_EDITS then match nothing
broken since e6f4464 (2026-10-28)

Legend: green = the branch with a body-slicer; red = the branch every other governed document takes. The failure is silent because an empty draft still parses into sections — they simply have no text.

2.3 Why no test caught it

measured grep -rn "build_corpus" knowledge/tests core/tests tests/ returns three hits: two strings inside assertions and one in a docstring. No test runs the generator. P3.1's own Fails if clause — "generating BPP then applying no manual step differs from the committed bpp.md" — was written and never implemented.

measured the broken draft still parses — into 28 sections whose combined body is 1,322 characters, almost all of it the headings themselves. An empty artefact therefore looks structurally valid to every guard that counts sections or chunks.

Even if it had been written, it would have skipped in the gate. The gate poisons PDFTOTEXT_BIN on purpose (D57), and the existing seam stub_ingest_extraction patches knowledge.ingest.extract_pages — not scripts/build_corpus.py, which imported the function directly. A regeneration test needs its own seam, or it is a test that never runs (testing_hazards.md §2.6).

So P4 is not a 15-page correction review. The text needs no edits; the review is a verification pass, like SAOSO's three edits in 1,537 blocks. That is a much cheaper task than the plan's wording implies — and a much worse one to attempt before the generator works.

2.5 The one thing the draft does change

All 28 sections agree on (section_ref, page) and disagree on heading_path: the PDF parser gives the part the clause sits in (five distinct values), the artefact gives each section its own name (28 values).

artefact:  2.2 PGS farm assessment and certification fee
pdf path:  II. Membership fees, farm assessment fees, licensing fees

read SAOSO already decided this, in P6: "“a ref:-annotated heading carried its # marker into the text, so every clause rendered at heading weight” and "“heading_path named the parent in one path and the section in the other → SaosoParser includes the section, per the format's own rule”. So the OPP parser has to learn the same rule; the artefact is not the thing to change.

2.6 And a third dependency, unrelated to the OPP

read knowledge/ingest.py, the artefact branch: "the artefact carries no printed TOC, and --from-corpus has no pages: the PDF is read again for this one purpose". So corpus_refresh --apply still needs pdftotext, and P7.4's gate — "the box needs no pdftotext for any of it", "remove poppler-utils and it still works" — cannot pass as written.

4Evidence for and against

A — P4 as written

Strongest case for

  • It is what the plan says, in the plan's own order.
  • No scope invention: the review discipline (flagged delta, kill criterion) is already written.
  • If the draft were fine, it is one session of reading.

Against

  • Step 1 exits 0 with 2,742 characters of page numbers. A reviewer would be reviewing nothing and would say so.
  • The declared-edits step cannot run: SystemExit "matched 0 times".
  • It would produce an artefact that loses 27,000 characters of the OPP, and the ingest has no way to notice — the count gate passes (30 chunks either way).

B — repair, test, then review

Strongest case for

  • It fixes the thing that makes P4, P5 and every future document impossible, in one line.
  • The measurement says the review itself is cheap: 28 of 28 sections text-identical, 30 chunks, 66 bullets intact.
  • It implements P3.1's own gate, which is a stated promise of a task already marked landed.
  • It leaves the next two documents (landscape, any reprint) working.

Against

  • Scope creep: the plan has no task for "repair the generator", so the plan needs amending rather than following.
  • The BPP does not regenerate cleanly even after the fix — 45 diff lines, 8 extra repeated side labels — so the regeneration test would be red for a reason that is not the OPP.
  • It delays the box by a session.

C — deploy first

Strongest case for

  • 98 commits undeployed is its own risk: the concordance, the answer surface, the reader and the drift commands are all unshipped.
  • It exercises corpus_check on a real box, which is the only place its operator-facing wording can be judged.
  • Local work continues either way; the box does not block it.

Against

  • P7.4's gate cannot pass (2.6), so the task ends "done except its proof".
  • corpus_refresh --apply would convert 2 of 4 documents; the other two keep serving PDF text, and the report would say so forever until P4/P5.
  • It is a deploy session, not a corpus session — a different kind of day.

D — TOC first

Strongest case for

  • It is the only way P7.4's proof can be made true, and the proof is the interesting half of P7.4.
  • The change is small if the TOC is preserved across a refresh: the PDF's sha256 has not changed, so the printed TOC cannot have.

Against

  • It is a decision (artefact carries the TOC, or refresh preserves it), and it defers the generator defect again.
  • Preserving the TOC hides a real question: what happens on a genuine reprint, when the TOC does change?

7Recommendation

B — repair the generator, make P3.1's gate real, then review the OPP as a verification pass. Four steps, in this order, each with a red test first:

  1. Negate keep in the generic branch and add the body furniture rule the BPP needs (its repeated The Principle Of Health. side labels: 12 in the draft, 4 in the committed artefact). Test: a generated BPP draft contains the BPP's own words, and regenerating bpp.md is a no-op diff.
  2. Give the regeneration test a seam that works under PDFTOTEXT_BIN=/usr/bin/true — patch the generator's import, or have it take pages. A test that skips in the gate is the hazard this repo keeps writing down.
  3. Teach OppParser the P6 rule (a section's heading_path names the section), so P4's identity gate means something.
  4. Generate the OPP artefact and review it — 15 pages, 28 sections, 30 chunks, and, per today's measurement, no text edits. Declare `CORPUS_EDITS` only if the review finds one; the review queue is not the document.

What this changes: P4 gains a step 0 in the plan, and P3's status moves from "landed" to "landed, with its gate now running".

What would change my mind:

  • If a release to the box is needed this week for a reason outside the corpus, C wins and P7.4 ships with its no-reader proof explicitly deferred.
  • If step 1 turns out to be more than the two changes measured here — if the OPP's draft, once generated, differs from the PDF path in more than heading_path — then P4 goes back to being review-bound and should be planned as such, with the flagged-delta list produced before anyone reads a page.
  • If the BPP's 45-line drift is judged too expensive to reconcile now, then the regeneration gate should be scoped to documents with a matching generator version, and that scoping must be written in the plan rather than discovered by the next person.

And then

In order, once B lands: P5 (landscape — 10 pages, the same shape, now cheap) → the TOC decision + P7.4 (so the box's proof can pass) → P6's step 4 (Appendices 3, 4 Table 1, 7) with Appendix 6b held behind its product decision.
